# 问题 1：聊天历史保留验收

日期：2026-10-18。基线：`e184735`。分支：`codex/preserve-chat-history`。
本次只修复“摘要改变用户可见聊天历史”，其余三个问题等待逐项验收后再处理。

## 改动

- `src/chat_history.py` 在个人数据库保存用户与模型原文，按账号、内部会话 ID 和消息 ID 隔离、去重。
- `src/server.py` 在执行前保存原始输入，历史接口读取独立记录；确认恢复仍使用原检查点协议。
- `src/agent/streaming.py` 在完整消息更新时提供保存回调，后续摘要不会覆盖已保存原文。
- 旧会话首次读取会遍历仍保留的检查点，按时间补回原始消息，过滤带 `lc_source=summarization` 的内部摘要。
- 异常时尽量保留已输出的部分回复，断连后后台完成仍可读取；进程强制终止前未保存的输出不保证完整。

这不会关闭摘要，也不会把完整历史重新塞回模型上下文。
现用个人数据未被测试脚本读取或重建；新表由应用启动时幂等创建。
历史已从所有检查点和备份中删除的内容不能凭摘要还原。

## 手动检查

临时验收应用使用真实摘要中间件与虚构模型，个人数据库为临时文件，不调用外部模型。

```powershell
.venv\python.exe scripts/run_frontend_test_app.py --summarize
```

打开 `http://127.0.0.1:18765/`，注册符合现有格式的测试账号，新建会话。

1. 连续发送四个普通问题，例如“历史测试1”至“历史测试4”，每次等待回答完成。
2. 页面应保留四条用户原文和四条回复，顺序正确。
3. 刷新页面，再新建另一会话、切回原会话，仍应有上述八条记录。
4. 不应出现内部摘要、“Here is a summary”或重复消息。
5. 在另一个会话发送“确认 GPA”，确认后刷新，原始问题和回复应各保留一次。

该临时应用有会话调用限额，测试较多时新建会话即可。
