# 问题 3：完整画像读取验收

日期：2026-10-18。基线：`a65650e`。分支：`codex/read-complete-profile`。
本次只修复画像读取默认只返回 10 个字段的问题，第四项索引路径问题尚未开始。

## 改动

`src/tools/profile.py` 原先只调用一次 `store.search(namespace)`，底层默认 `limit=10`，
因此写入超过 10 个字段后，工具仍返回成功，却遗漏其余字段。

现在每批显式读取 100 条，通过 `offset` 继续读取，直到最后一批不足 100 条。
100 是每批数量，不是画像总字段上限；整批结束时会继续查询，确认没有遗漏。
所有页都使用当前用户的画像命名空间，返回 JSON 的结构不变。
任意一页读取失败时沿用异常传播，不把已经读到的部分内容当作成功的完整画像。

这次不需要迁移数据库，也不需要重写已经保存的画像字段。后端进程重启后生效。

## 可重复验证

在项目根目录运行：

```powershell
.venv\python.exe scripts/test_profile.py
```

此脚本使用合成字段、真实 `ToolRuntime`、内存存储和临时 SQLite，不读取现用个人数据库，
也不调用模型或外部数据库服务。

六项测试覆盖：

1. 通过写入工具保存 12 个字段，再通过读取工具完整取回；修复前稳定失败：`10 != 12`。
2. 在内存和 SQLite 两种存储上验证 0、1、10、11、99、100、101、200、205 个字段，逐项比较内容。
3. 两种存储下分页读取均隔离不同用户，包括名称前缀相同的账号，并排除其他顶层命名空间。
4. SQLite 关闭并重新打开后，205 个字段及覆盖更新的值仍完整返回。
5. 后续页读取发生异常时，调用失败，不返回成功的部分画像。
6. 存储未挂载、身份缺失或为空时拒绝访问，避免进入共享匿名命名空间。

专项六项测试已通过，并已加入 `scripts/check_offline.py`。
