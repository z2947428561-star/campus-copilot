# 存储一致性与索引发布实施计划

日期：2026-10-18。基线：d352a18。来源：最初架构分析第 4 项，用户要求“推进4”。

## 1. 需求

- R-1 重建失败仍可检索：现用索引不能在新版本完成前被删除。
- R-2 发布可追踪、可回滚：构建版本、配置与切换结果可检查，并发发布不能覆盖较新的切换。
- R-3 存储职责独立：个人数据和会话不依赖鉴权内部连接；成绩并发更新保留学分快照。

## 2. 大致做法

### R-1 重建失败仍可检索

- 做法：Milvus、Chroma 都写入独立集合，验数与自查询通过后登记为可发布。
- 涉及：建库、检索与数据库浏览器。
- 测试入口：知识库构建、检索与发布公开函数。
- 验收：嵌入或写入失败不切换；读取缺失索引不创建集合；新检索能发现成功切换。
- 难点：旧集合没有版本记录，保留只读兼容，不能推断其模型配置。

### R-2 发布可追踪、可回滚

- 做法：本机 SQLite 登记候选版本，以递增修订号在事务中切换；保留上一集合，回滚同样校验修订号。
- 涉及：索引登记、命令行和数据库浏览器版本信息。
- 测试入口：构建、发布、回滚公开函数及命令行。
- 验收：过期发布被拒绝；候选版本可单独验收；回滚恢复旧文本；模型不匹配时拒绝读取。
- 难点：向量集合与登记库不能跨库提交，先完成不可变集合，再切换指针。

### R-3 存储职责独立

- 做法：抽出个人数据库连接、事务和占位符；成绩使用数据库原子更新，公共课程查询保持只读。
- 涉及：鉴权、个人数据、会话、记忆路径和数据浏览器。
- 测试入口：连接公开函数、成绩与课程公开函数。
- 验收：异常事务回滚；只读连接不能写；重复选课幂等；并发成绩更新不丢失原学分。
- 难点：保持 PostgreSQL 与 SQLite 的现有表结构和参数语义。

## 3. 阶段与任务

阶段 4：用户能安全替换索引、回滚，并继续使用原有个人数据。

1. 贯通候选索引构建、检索、原子发布和回滚。
2. 收拢个人数据库连接并修复成绩、选课更新的一致性。
3. 连接建库命令、数据浏览器版本信息，完成回归与说明。

证明：真实临时 Chroma 故障与切换测试、Milvus 驱动契约、SQLite 并发与事务测试、离线回归。
范围：单机共享登记库；不引入跨主机协调，不自动删除旧集合，不复制或改写本机私有数据库。
