# 命令、浏览器与交付

## 1. 任务位置

阶段 4 让用户安全替换索引；本任务交付 R-1 重建失败仍可检索、R-2 发布可追踪、可回滚和 R-3 存储职责独立。
前置：索引发布与存储接口完成。后续：用户按说明操作实际后端。
范围：命令行、版本展示、使用说明；不发布真实服务或触发付费嵌入。

## 2. 开发上下文

**先读**
- `scripts/build_kb.py` — 如何保留文档切分并替换破坏性重建？
- `src/database_browser.py` — 如何浏览当前生效的物理集合？
- `frontend/js/database.js` — 版本信息在哪里展示？
- `scripts/check_offline.py` — 如何在公开数据隔离副本中回归？

**已定**：发布需要修订号；浏览器仅展示；旧集合不自动删除；保留用户未提交修改。

**接口与范围**：建库命令、数据浏览器接口及既有页面版本说明。

**执行**：`.venv\python.exe scripts/check_offline.py`；`node --check frontend/js/database.js`。

**未知**：外部 Milvus、PostgreSQL 不可用不冒充实测；失败状态需可诊断。

## 3. 工作流

1. 阅读上下文，重述：命令与浏览器共用生效索引版本。
2. 写浏览器在发布后读取新集合的失败测试并提交。
3. 替换建库流程，增加暂存、状态、发布与回滚命令。
4. 展示修订与候选信息，补充运行与恢复说明。
5. 完成离线回归、汇总并提交。

## 4. 验收案例

| 案例 | 输入 | 预期 | 接口 |
|---|---|---|---|
| 状态查询 | 暂无登记 | 显示旧版兼容，不建库 | 命令 |
| 分步发布 | 暂存后指定修订 | 成功切换 | 命令 |
| 新版浏览 | 发布新集合 | 分块与修订同一版 | 浏览器 |
