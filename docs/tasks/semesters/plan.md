# 多学期实施计划

日期：2026-10-18。基线：数据库可视化完成后的 b41bc9e。

## 1. 需求

- R-1 学期归属明确：最初架构分析第 3 项，用户要求“推进3”。
- R-2 个人数据与工具按学期查询：同一请求，成绩、选课、排课不能串学期。
- R-3 网页选择与运行上下文一致：同一请求，确认恢复不能换学期执行。

## 2. 大致做法

### R-1 学期归属明确

- 做法：登记学期与资料版本；提供保留旧数据的迁移、单学期事务导入和旧结构读取兼容。
- 涉及：公共校历与排课；旧九月学期个人存储名称保留兼容。
- 测试入口：学期登记、迁移与导入公开函数。
- 验收：两个学期可以有相同周次；无关学期不被覆盖；导入失败回滚；版本检查防止覆盖。
- 难点：旧结构没有学期归属，仅能在唯一旧校历下明确映射，不能猜测混杂数据。

### R-2 个人数据与工具按学期查询

- 做法：显式学期优先，其次运行上下文；个人记录保留账号隔离；新成绩保存学分快照。
- 涉及：成绩、选课、校历、课表与空教室工具。
- 测试入口：个人数据函数、工具调用和 HTTP 接口。
- 验收：同一门课跨学期独立；GPA 单学期计算；缺排课说明未录入；无事件不崩溃。
- 难点：旧成绩缺少学分快照须说明回退，新成绩不能随课程目录修改而改变 GPA。

### R-3 网页选择与运行上下文一致

- 做法：共用学期选择；请求携带学期；待确认操作保存学期并在恢复时核对。
- 涉及：Web、运行上下文、会话登记、数据库浏览器及使用说明。
- 测试入口：真实 HTTP 与临时应用的浏览器交互。
- 验收：切换不串数据；刷新恢复确认学期；错误学期恢复返回冲突；旧账号与旧接口可用。
- 难点：异步查询返回顺序和跨标签页登录变化不能把旧数据放回页面。

## 3. 阶段与任务

阶段 3 多学期数据可以独立使用，覆盖以上三项需求。

1. 建立学期登记、保留数据的迁移与版本化导入。
2. 贯通个人数据和业务工具的学期范围。
3. 加入网页学期选择与确认恢复保护，完成回归和交付。

证明：迁移与双学期回归、工具回归、浏览器切换与确认恢复。
本阶段不抓取新校历、不伪造未来学期，不实现跨学期累计 GPA 或政策版本自动判定。
