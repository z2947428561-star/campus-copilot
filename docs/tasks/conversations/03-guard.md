# 限额反馈与并发保护

日期：2026-10-17 · 版本：1

## 1. 位置

- Phase 1 用户能够持续管理自己的会话：让执行状态与界面反馈一致。
- 推进 R-3 限额反馈与并发保护，完成阶段回归。
- 前置：历史与确认恢复。后续：本阶段总结。

## 2. 开发所需

**先读**
- `src/server.py` — 工作线程与响应流何时结束？
- `src/agent/middleware.py` — 模型与工具限额如何挂载？
- `src/agent/streaming.py` — 哪些图事件尚未展示？
- `scripts/test_frontend.js` — 隔离浏览器回归如何运行？

**已定**：本机单进程；同会话串行，不同会话独立；断连不提前放开执行锁，见 plan.md。
**接口与范围**：聊天 HTTP、无网络 Agent 图和浏览器；不实现分布式锁或强制杀模型请求。
**运行**：`.venv\python.exe scripts/check_offline.py`；`.venv\python.exe -m compileall -q src scripts`；浏览器回归见 docs/frontend.md。
**未知**：中间件限额事件需用安装版本的真实图验证，不能只依赖 mock。

## 3. 步骤

1. 阅读第 2 部分，确认任务是保证会话执行互斥并解释限额状态。
2. 编写并发、失败释放和限额反馈的失败用例。
3. 实现执行保护、有界事件队列和限额反馈。
4. 增加单轮配置并验证真实假模型图。
5. 执行离线与浏览器回归，更新说明并提交。

## 4. 用例

| 用例 | 输入 | 预期 | 接口 |
| --- | --- | --- | --- |
| 并发 | 同会话同时请求 | 后一个返回 409 | HTTP |
| 独立 | 不同会话同时请求 | 各自可以执行 | HTTP |
| 释放 | 执行抛异常后重试 | 会话锁已释放 | HTTP |
| 限额 | 极低的单轮与累计阈值 | 明确反馈且可新建会话 | Agent 图 |
| 断连 | 请求运行中关闭连接 | 结束前保持忙碌 | HTTP |
