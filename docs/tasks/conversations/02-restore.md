# 恢复历史与确认操作

日期：2026-10-17 · 版本：1

## 1. 位置

- Phase 1 用户能够持续管理自己的会话：让刷新后的页面与检查点一致。
- 推进 R-2 历史与确认恢复；只展示检查点保留的聊天消息。
- 前置：创建与切换会话。后续：限额和忙碌状态复用详情响应。

## 2. 开发所需

**先读**
- `src/server.py` — 会话归属和恢复请求在哪里校验？
- `src/agent/streaming.py` — 中断如何转成确认动作？
- `src/agent/memory.py` — 检查点怎样持久化？
- `frontend/js/chat.js` — 页面如何恢复选中会话？

**已定**：检查点是消息和待确认操作的来源；决定绑定检查点版本，见 plan.md。
**接口与范围**：详情与聊天 HTTP 接口、页面刷新；不创建第二份消息档案。
**运行**：`.venv\python.exe scripts/test_conversations.py`；`.venv\python.exe -m compileall -q src scripts`。
**未知**：恢复快照的消息可能已摘要；缺失历史不得伪造。

## 3. 步骤

1. 阅读第 2 部分，确认任务是恢复可展示的消息与尚未执行的确认动作。
2. 编写历史与待确认快照的失败用例。
3. 实现快照投影和恢复决定的校验。
4. 展示全部待确认动作，刷新后允许提交批准或拒绝。
5. 验证过期决定和数量错误，提交本任务改动。

## 4. 用例

| 用例 | 输入 | 预期 | 接口 |
| --- | --- | --- | --- |
| 历史 | 含用户、模型、工具消息的快照 | 只显示聊天内容 | HTTP |
| 刷新 | 持久化待确认快照 | 确认操作仍可见 | 浏览器 |
| 过期 | 旧检查点版本 | 409 且不执行 | HTTP |
| 多动作 | 两个待确认动作 | 展示并提交两个决定 | 浏览器 |
| 乱序操作 | 等待确认时发新消息 | 拒绝并提示处理确认 | HTTP |
