# 会话生命周期实施计划

日期：2026-10-17 · 版本：1

本阶段让用户新建和切换会话，刷新后恢复消息与确认操作，并在并发或限额触发时得到明确反馈。
继续采用本机单进程。旧主会话保留，长期画像按用户共享。
历史来自检查点；已经摘要压缩的逐字记录不重建。

## 1. 需求

- R-1 会话创建与隔离：来自架构分析第 1 项及用户“先推进1”。
- R-2 历史与确认恢复：来自架构分析第 1 项及用户“先推进1”。
- R-3 限额反馈与并发保护：来自架构分析建议推进顺序第 1 项。

## 2. 逐项方案

### R-1 会话创建与隔离

- **方法**：持久化用户与会话的归属，服务端映射检查点标识；网页提供选择器和新建按钮。
- **涉及**：Web 入口、个人数据库、聊天界面。
- **测试接口**：已鉴权的 HTTP 会话接口与浏览器界面。
- **验收**：新会话上下文独立；旧主会话可选；其他用户无法读取或使用会话。
- **难点**：兼容旧客户端的默认主会话，同时禁止客户端指定任意检查点标识。

### R-2 历史与确认恢复

- **方法**：从检查点投影可展示消息和待确认动作；恢复决定绑定检查点版本。
- **涉及**：聊天状态读取、流式确认协议、页面初始化。
- **测试接口**：会话详情 HTTP 接口、聊天 HTTP 接口与浏览器刷新。
- **验收**：刷新恢复保留的消息；确认操作可继续；过期决定拒绝；多动作全部展示并提交。
- **难点**：摘要后仅能展示保留的消息；工具内部内容不作为普通聊天展示。

### R-3 限额反馈与并发保护

- **方法**：同会话只运行一次；单轮与累计限额分别配置；输出明确的限额事件。
- **涉及**：聊天执行、中间件、流式协议、界面状态。
- **测试接口**：聊天 HTTP 接口、无网络的真实 Agent 图与浏览器界面。
- **验收**：同会话并发返回冲突；不同会话可运行；触顶可新建会话；断连不释放仍运行的会话锁。
- **难点**：同步模型调用不能强制终止；断连后保留执行锁并丢弃无人消费的事件，直至执行结束。

## 3. 阶段

### Phase 1 用户能够持续管理自己的会话

**覆盖**：R-1 会话创建与隔离、R-2 历史与确认恢复、R-3 限额反馈与并发保护。
**目标**：用户可以新建会话、刷新后继续，并理解何时需要等待或新建会话。

- 打通会话登记、归属校验、选择与新建的完整路径。
- 恢复检查点消息和确认状态，并验证决定的版本与数量。
- 限制同会话并发，呈现限额反馈，完成回归与使用说明。

**证明**：隔离 HTTP 测试、真实图的假模型测试、浏览器回归通过。
**范围外**：分布式执行、强制终止已发出的模型请求、完整逐字档案、多学期和政策库改造。
