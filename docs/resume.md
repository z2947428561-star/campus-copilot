# 简历项目段落(campus-copilot)

## 项目名(一行)

**Campus Copilot —— 校园教务智能助手(Agent + RAG)**|个人独立开发|2026.09

## 一句话介绍

面向厦门大学马来西亚分校学生的多用户智能助手:LangChain Agent 驱动,
结构化数据工具(校历/课表/教室/GPA)与教务政策 RAG 双数据源协同,
带记忆、脱敏、降级、人工确认等生产级治理,已通过 31 项评估集验收。

## 技术栈

Python · LangChain 1.x(create_agent / Middleware / Hook)· LangGraph(Checkpointer / Store)
· Chroma 向量库 + Ollama bge-m3 Embedding · SQLite · FastAPI / SSE 流式 · Pydantic

## 亮点(按面试价值排序,数字为实测)

1. **Agent 工具路由**:8 个工具(教学周计算/空教室查询/GPA 结构化报告/先修链递归展开/
   政策向量检索/长期记忆读写),26 项路由评估 **22 项正确(85%)**,
   剩余失败项定位为 LLM 非确定性并已记录归因
2. **RAG 全链路**:采集 16 份学校官方公开教务文档(含来源元数据)→ 切分向量化入
   Chroma(48 片段)→ 相似度 + 元数据混合检索(过滤召回与全库召回按分数合并,
   解决"问题表面类型 ≠ 文档分类"的过滤陷阱)→ 回答强制附官方出处,
   10 项检索抽查 **10/10 命中**正确文档
3. **生产级治理(中间件栈,洋葱圈 6 层)**:PII 自定义检测器(中/马手机号 + 学号,
   修复过中文紧贴数字导致 `\b` 失效的真实 bug)、长对话自动压缩、
   云端模型故障自动降级到本地 Ollama、敏感工具(成绩分析)执行前人工确认
   (HITL 中断跨 HTTP 请求恢复)、全链路调用耗时审计日志
4. **多用户持久记忆**:短期会话(Checkpointer 按 thread 隔离,重启续聊)+
   长期画像(Store 按用户隔离,工具自动读写,GPA 分析结果自动归档);
   31 项综合评估通过率 **81%**,PII 红线零回显
5. **服务化**:FastAPI + SSE 流式接口 + 零依赖 Web 聊天页;
   Docker Compose(app + PostgreSQL,记忆后端一行环境变量切换);
   全链路 LangSmith 追踪

## 面试常问 & 你的答法

- *为什么双数据源?* 教务信息天然两半:课表/教室/成绩是结构化的,精确查;
  政策规定是非结构化的,必须检索原文并引用,不能让 LLM 背政策。
- *最大的坑?* HITL 的 resume 必须有 checkpointer 存现场,没有持久化层直接
  RuntimeError——因此把 M4 的记忆持久化提前设计进来;
  以及元数据过滤反而降低召回的案例(费用问题被过滤到 finance 类,漏掉 academic 类的重修费条款),
  用混合检索解决。
- *81% 剩下的 19% 是什么?* 主要是 LLM 工具调用非确定性(评估跑两遍失败集合不同),
  已定位到模型行为层面,加固方向是 tool_choice 强制与温度调参。
