# 多学期与资料版本

更新：2026-10-18。学期使用稳定 ID，与显示名称、课程目录的建议开课月份分开。
网页、个人数据、校历、排课和 GPA 共用学期范围。仓库仍只附带既有九月学期资料，未编造新校历。

## 如何使用

登录后，在会话栏选择学期。个人数据面板只显示所选学期的选课与成绩。
同一门课程可在不同学期分别录入，删除只影响当前学期。选择按账号保存在当前标签页中。
发起聊天时会携带学期，工具未显式指定学期时使用该选择。

工具回答包含学期 ID；排课与校历同时说明资料版本。查询其他学期可先调用
`list_available_semesters`，再传 `semester_id`。明确日期的校历查询会按日期寻找唯一覆盖的学期。
日期未覆盖或范围重叠时说明无法确定，不拿其他学期的周次作答。

默认优先选择覆盖校园今天的唯一学期。今天不在任何已录范围时，个人数据选择最近过去的学期，
没有过去学期则选择最早未来学期；面板标明“非当前日期范围”。范围重叠时需要明确选择。
校园日期按 UTC+8 计算；这些默认规则不改变显式日期校历查询的覆盖要求。

待确认操作会保存发起时的学期，刷新后恢复；处理中与待确认期间选择器锁定。
HTTP 层也会拒绝用其他学期恢复同一个操作，编辑确认参数也不能改变原 GPA 操作的有效学期。
保存的是学期范围，执行时仍读取该学期当前保存的数据。
历史中断若没有学期登记，只能在唯一旧学期可确定时恢复；无法确定时需要取消并重新发起。

## 数据模型

| 数据 | 学期归属 | 说明 |
|---|---|---|
| 学期登记 | semester_id | 名称、学年、起止日期、资料版本、排课覆盖状态 |
| 教学周 | semester_id + week_no | 不同学期可以各自有第 1 周，周数不固定为 14 |
| 排课与学期事件 | semester_id | 查询只使用指定学期的记录 |
| 成绩与选课 | 账号 + 学期 + 课程 | 不因切换学期覆盖其他记录 |
| 成绩学分快照 | 随成绩保存 | 保存录入时学分与名称，修改成绩时保留已有快照 |

旧个人记录的 `September Semester 2026` 存储键继续使用，外部统一映射为 `2026-09`。
新学期使用其 ID 存储。迁移不批量改写或删除旧个人记录。
课程目录中的 `Sep`、`Apr` 等仅表示建议开课月份，不等于某个具体学期已排课。

GPA 是所选学期的加权 GPA，不是累计 GPA。新记录使用保存的学分；旧记录缺少快照时，
回退当前目录并在报告中说明历史学分未核实。目录缺课且没有学分快照时不会猜测 GPA。
只读数据浏览器新增“学期与版本”，并显示排课、校历的学期归属及个人成绩快照。

`schedule_status=unavailable` 表示未提供排课，不能据此报告所有教室空闲。
`recorded` 表示该学期已导入一份排课资料；空闲结果仍仅是对已录入占用的推算。
时间段部分重叠也会计为占用；未登记的教学周不能推算空教室。

## 旧公共库迁移

旧结构可以通过只读兼容路径使用，不会在浏览、查询或 Web 启动时重建公共库。
若旧校历只有唯一学期，可明确映射其原有周次、排课与事件。混杂多个学期而排课无归属时拒绝猜测。
个人表的两个可空快照字段和会话学期登记表由现有应用启动流程补齐。

准备导入更多学期前，可先迁移公共结构：

```powershell
.venv\python.exe scripts/import_semester.py --migrate
```

迁移事务保留旧排课 ID 与记录，包括未指定课程的教室占用；失败则回滚。重复执行不会重复迁移。
`scripts/init_db.py` 仍是原有的清空重建命令，只用于明确重置公共演示库，不能用于保留日常数据的迁移。

## 导入一个学期

把已经核实的学期信息保存为 JSON，再运行：

```powershell
.venv\python.exe scripts/import_semester.py --file semester.json
```

JSON 结构示例仅说明格式，以下日期是演示，不是新增官方校历：

```json
{
  "semester_id": "2027-04",
  "label": "演示格式，请替换为已核实学期",
  "academic_year": "2026/2027",
  "start_date": "2027-04-01",
  "end_date": "2027-05-01",
  "source": "example-only",
  "is_demo": true,
  "weeks": [
    {"week_no": 1, "start": "2027-04-05", "end": "2027-04-11", "type": "teaching"}
  ],
  "events": [],
  "timetable": null
}
```

排课数组中的每项包含 `course_id`、`room`、`weekday`、`period`、`weeks`。
例如时段为 `08:30-10:00`，教学周范围为 `1-1`。课程和教室须已经存在；无课程的占用可用 `null`。
`timetable: null` 或省略字段表示未录入排课；空数组表示明确提交一份无占用记录的资料。
周次须从 1 连续编号，日期须落在该学期范围内，排课周范围必须有校历支持。

更新同一学期时须指定已核对的版本：

```powershell
.venv\python.exe scripts/import_semester.py --file semester.json --expected-version 1
```

相同内容重复导入不增加版本；不同内容需要匹配当前版本。事务只替换该学期的校历、事件和排课，
其他学期和个人数据保持不变。导入的是完整学期快照，不是局部补丁；历史输入 JSON 需另行保留。
导入后刷新页面以加载学期目录；运行中的旧版本应用需要重启后使用新查询规则。
版本号用来辨识当前资料修订，目前不提供旧版本历史归档查询。
可用 `--database` 显式选择另一个已存在的公共 SQLite 文件；不会为错误路径创建新库。

## 接口与验证

- `GET /api/semesters` 返回可选学期、日期、版本与默认选择，需要登录。
- 个人数据 GET/DELETE 使用查询参数 `semester_id`，PUT 使用同名请求体字段。
- `POST /api/chat` 接受可选 `semester_id`；旧请求不传时仍按确定的默认学期运行。
- 会话详情返回已保存的 `semester_id`，供刷新恢复处理中或待确认操作。

```powershell
.venv\python.exe scripts/test_semesters.py
.venv\python.exe scripts/test_semester_data.py
.venv\python.exe scripts/test_semester_context.py
```
