**1．学期资料需要作为一个快照读取**

[空教室查询](<E:/Campus Copilot/src/tools/timetable.py:51>) 先通过 `selected_semester()` 获取版本和覆盖状态，再另开连接读取周次、排课和教室。[课程课表查询](<E:/Campus Copilot/src/tools/timetable.py:83>) 也采用这一结构。[公共库连接](<E:/Campus Copilot/src/semesters.py:23>) 的 `query_only` 防止写入，但没有建立涵盖多次读取的显式事务。

临时数据库中复现了两种情况：

- 读出版本 1 后，由独立线程导入版本 2，将教室 A101 改成 A102；查询返回 `data_version=1`，内容却是 A102。
- 读出旧的 `recorded` 状态后，导入 `timetable=null`；空教室工具仍返回 `ok=true`、`recorded` 和 24 间空教室，而新版本实际状态为 `unavailable`。

触发条件是查询与导入重叠。没有发生并发导入时，不能据此声称普通查询必然错误。

建议在公共资料模块中提供一次完整的学期资料读取，内部管理连接和事务，返回同一版本的元数据与内容。仅给第二个连接补 `BEGIN` 仍然不够，学期解析也必须进入同一快照。验收时，返回完整旧版本或完整新版本都可接受，混合版本必须被排除。

**2．历史学分的“未知”不应因编辑成绩而消失**

[成绩更新 SQL](<E:/Campus Copilot/src/student_data.py:51>) 用 `COALESCE` 将旧记录缺失的快照填为当前课程目录学分。[读取成绩](<E:/Campus Copilot/src/student_data.py:86>) 只要快照非空，就标记为 `grade_snapshot`；[GPA 警告](<E:/Campus Copilot/src/tools/gpa.py:139>) 随之消失。

合成案例中，CS101 的旧成绩没有学分快照，CS102 有快照：

| 操作 | GPA | 历史未核实警告 | CS101 学分来源 |
| --- | --- | --- | --- |
| 目录中 CS101 为 4 学分 | 3.33 | 有 | 当前目录回退 |
| 目录改为 1 学分，尚未编辑成绩 | 3.67 | 有 | 当前目录回退 |
| 原样保存旧成绩 3.0/B | 3.67 | 无 | 被标记为历史快照 |

数值变化由目录更新引起。普通编辑的缺陷是固化回退值并取消不确定性提示，而不是这次保存单独改变了 GPA。

建议更新已有成绩时保留缺失快照，或记录 `catalog_fallback`、`verified_historical` 等明确来源。补齐历史学分需要独立核实，不能隐含在改分数操作中。长期再将课程学分、先修关系关联到适用学年或培养方案。

**3．历史和个人数据需要独立的可用性边界**

[会话详情](<E:/Campus Copilot/src/server.py:300>) 在读取归档前调用 `get_web_agent()`。[Agent 组装](<E:/Campus Copilot/src/agent/assistant.py:103>) 创建模型，而[模型工厂](<E:/Campus Copilot/src/model.py:74>) 在缺少 API key 时抛出异常。

真实临时 HTTP 探针先保存一条聊天原文，再将模型 key 设为空：数据库仍有一条原文，`GET /api/conversations/{id}` 返回 500。此处证明的是模型初始化失败的影响，没有模拟所有外部模型故障；已构造的模型遇到远端故障不一定阻止历史读取。

前端的[控件状态](<E:/Campus Copilot/frontend/js/chat.js:31>) 又用聊天 `ready` 控制公共学期选择。离线 JS 探针确认会话详情失败后，学期选择保持锁定，连带影响仍可打开的个人成绩/课程面板。

建议把归档读取、执行状态读取和执行新请求分开：已有原文可直接读取；检查点状态不可用时明确标记状态未知，并禁止不安全的恢复操作。学期目录加载成功即可支持个人数据浏览，聊天和待确认操作保留各自的学期约束。

**4．前端需要统一异步操作的归属**

- **新建会话被旧轮询取消。** [运行中会话](<E:/Campus Copilot/frontend/js/chat.js:117>) 预约 1.5 秒轮询，[新建操作](<E:/Campus Copilot/frontend/js/chat.js:125>) 没有取消它。新建 POST 较慢时，旧轮询进入 `open()` 并中止该请求，页面回到旧会话。探针确认取消发生；真实服务端可能已经完成创建，但本轮没有实证这一附加结果。
- **旧退出清除新登录。** [退出逻辑](<E:/Campus Copilot/frontend/js/auth.js:63>) 等待 HTTP 后无条件清理共享会话。等待期间另一标签页登录新用户，旧请求完成仍会清空新会话。探针确认本地状态丢失；旧退出请求携带旧 token，不会因此撤销新用户的服务端 token，也未发现此路径越权。

建议每次会话操作取得自己的版本与取消句柄，轮询绑定其发起会话；新建开始时立即撤销旧轮询。登录、退出和跨标签页变化也使用统一的 session 版本，迟到结果只能清理自己的版本。验收应使用受控响应与定时器，覆盖慢响应和乱序完成。

**5．画像日志应减少个人内容副本**

[保存画像](<E:/Campus Copilot/src/tools/profile.py:90>) 在成功后将 `user_id`、key 和完整 value 写到 INFO 日志；Web 默认 INFO 级别。合成画像的原值确实出现在日志捕获中。

建议保留操作名、字段名、成功/失败及必要关联信息，去除原值。画像查看、纠错、删除和清空功能可以后续单独建设。此项可以做成较小、独立的修复，不需要先重写画像存储。

**6．发布登记应对应实际发布内容**

[发布流程](<E:/Campus Copilot/src/kb.py:165>) 校验 ready 状态、embedding 配置、集合度量和分块数量，没有核对已登记的 `content_hash`。普通回滚复用这条路径。

真实临时 Chroma 中，先构建候选，再修改一个分块正文并保持数量：恢复校验拒绝内容摘要不一致，但 `publish_index()` 仍成功切换至 revision 2，检索读到修改后的正文，登记摘要仍为原值。

该问题需要候选构建后的外部维护或异常写入触发，普通网页用户没有直接修改集合的入口。建议将恢复时已有的内容核验推广为后端统一能力，覆盖发布和普通回滚，检查正文、元数据与分块标识。同时明确候选就绪后的集合不可变规则，避免校验与切换之间再次写入；摘要校验也不等同于证明向量质量或回答正确。

**7．后台任务生命周期需要独立管理**

[聊天入口](<E:/Campus Copilot/src/server.py:513>) 每轮启动 daemon 线程；[断连策略](<E:/Campus Copilot/src/agent/web_runs.py:62>) 停止投递但继续执行；[应用退出](<E:/Campus Copilot/src/server.py:88>) 直接关闭记忆连接，没有登记并等待这些线程。

合成阻塞工作线程的生命周期探针确认：任务仍处于 active 时，退出钩子已经调用 `close_memory()`。本轮未通过真实进程停机复现数据丢失，因此结论限于关闭顺序存在缺口。对于仍连接的 HTTP 请求，服务器自身可能等待响应；需要补齐的是断连后继续执行等后台路径。

建议由一个运行管理模块拥有任务登记、并发容量、执行截止时间和停机流程。停机时先停止接受新任务，再限时等待已有任务，最后关闭资源。现有单次模型超时和调用次数限制不能替代整轮截止时间。取消应在可控边界停止后续执行，不应假定 Python 工作线程可以安全强杀。

**知识库和工程保障的后续建设**

1. **政策资料补证。** 当前 `data/raw_docs` 的 16 篇政策资料仍全部为 `manual_summary`，`collected_at`、`effective_date` 均为 `unknown`。应逐篇补官方原文、采集/生效日期、适用范围与失效关系，并明确未核实条目。当前代码的来源标签有价值，资料质量仍需要真实核实；本轮没有上网核对政策。
2. **最终回答的证据约束。** 检索层已有证据过滤和稳定引用 ID，但[流式输出](<E:/Campus Copilot/src/agent/streaming.py:158>) 直接发送模型文本。合成图在“证据不足”后输出虚构证据 ID 和政策数字，文本仍原样发送；同一文本被现有离线评测判为四项失败。这证明运行链路没有执行这些机械检查，不能据此估算真实模型的错误率。建议政策回答保存本轮证据集合，接入 ID/URL/引文与拒答规则，设计校验失败后的回答方式，再补真实检索到最终答案的评测。机械校验通过也不能证明语义完全正确。
3. **验收自动化。** [CI](<E:/Campus Copilot/.github/workflows/ci.yml:26>) 运行 Python 语法和离线测试，现有五份浏览器回归未接入。本轮 JS 探针采用模拟 DOM/请求/定时器，也没有进入 CI。应自动启动已有临时测试应用，把浏览器回归和确定性竞态测试纳入 PR 检查。
4. **依赖和真实后端。** 尚无完整依赖锁文件，部分直接依赖只有下限，传递依赖也会重新解析。当前 PostgreSQL/Milvus 主路径还需要对应的真实集成检查；本轮只用 SQLite、临时 Chroma 和内存替身，不能将其等同于已验证真实主路径。

用户新增的 SurviveXMUM 采集保持了合理边界：[采集器](<E:/Campus Copilot/scripts/crawl_survivexmum.py:218>) 默认写入独立本地目录并标记 `student_wiki`，[政策构建](<E:/Campus Copilot/scripts/build_kb.py:77>) 仍扫描政策资料目录，[来源规则](<E:/Campus Copilot/src/policy_evidence.py:19>) 只接受两种政策来源。按当前默认流程，采集内容不会自动混入政策索引。这一隔离应继续保留。
