# 存储一致性与知识库发布

当前适用于同一主机上的 Web、CLI 和建库进程。政策索引采用独立集合构建、验证后切换，失败不会清空正在使用的集合。

## 构建与发布

在项目根目录运行，Conda 环境使用 `.venv\python.exe`，标准 venv 使用对应解释器。

```powershell
# 只读发布记录，不连接向量服务或调用 Embedding
.venv\python.exe scripts/build_kb.py --status

# 默认：构建新集合，验证后自动发布
.venv\python.exe scripts/build_kb.py

# 或者分步验收：先构建候选集合，当前版本保持不变
.venv\python.exe scripts/build_kb.py --stage-only
.venv\python.exe scripts/build_kb.py --status

# 将下面的版本 ID 和修订号替换成状态输出中的实际值
.venv\python.exe scripts/build_kb.py --publish <generation> --expected-revision <revision>

# 回滚到上一生效版本，同样使用刚检查的当前修订号
.venv\python.exe scripts/build_kb.py --rollback --expected-revision <revision>
```

构建可能调用已配置的云端 Embedding。`--status`、发布和回滚不生成向量；发布与回滚仍会连接向量服务验收目标集合。
命令里的 `<generation>`、`<revision>` 是占位说明，实际运行时需替换，不能原样复制。

每个候选版本登记物理集合名、构建时间、分块数、分块内容与元数据的哈希、Embedding 配置指纹和基线修订号。
状态为 `building`、`ready` 或 `failed`。`ready` 表示构建验收通过，是否生效以 `active` 指针为准。

构建按批检查向量数量、维数、有限值和非零长度；再检查集合数量、COSINE 度量、原文自查询及来源元数据。
这些检查证明存储构建完整性；真实问题的召回质量仍需用[政策评测](policy-evidence.md)校准。

发布在 SQLite 事务中比较修订号，再切换生效指针。两个候选基于相同修订构建时，只有一个能以该修订发布。
冲突者仍保留为 `ready`，需要重新检查状态，再决定是否指定新修订发布；程序不会自动覆盖。

## 检索、可视化和旧索引

检索每次读取生效指针，发现修订改变后换用新集合，无需重启应用。
已开始的查询继续使用它取得的集合；旧集合不会被自动删除。
数据库浏览器的索引页使用同一指针，展示实际集合、版本、修订号和构建时间，不调用 Embedding。

没有发布记录时，以原 `MILVUS_COLLECTION` 为旧版集合只读接入，状态标为 `legacy`。
读取缺失集合会返回不可用，不创建空集合。首次发布保留旧集合；若旧集合本来不存在，回滚到旧版会拒绝。
旧集合缺少构建记录，不能核实它的模型版本；来源字段缺失仍遵循原证据过滤规则。

新版本记录 Embedding 模型、端点、维数和相关参数的指纹。配置改变后，检索拒绝使用不匹配的新版索引。
切换 Milvus/Chroma、数据库名、逻辑集合名或独立的 Chroma 存储位置会进入不同登记范围。
Chroma 新登记以向量目录相对于登记库所在目录的位置为身份；整套项目换目录、相对布局不变时，版本仍可识别。
Windows 不同盘符无法计算相对位置时，保留绝对位置隔离，可使用下述重绑定命令迁移。

## 文件、故障和恢复

`KB_REGISTRY_PATH` 默认是项目根目录下的 `data/kb_releases.db`；相对路径统一相对项目根目录。
构建、Web、CLI 必须共用同一登记库及向量后端配置。登记库不包含 API key、连接密码或完整连接字符串。

备份前停止建库和写入，关闭使用 Chroma 的进程，再同时备份登记库和整个 `CHROMA_DIR`。
恢复时使用配套文件，保持二者的相对布局，并把配置指向恢复位置；相对路径仍相对项目根目录。
只复制向量集合或只恢复登记库，不能恢复完整的发布状态。

旧版绝对路径登记在原位置仍可读取，`--status` 不会修改登记库。
下一次构建、发布或回滚会在同一事务内迁移为新登记格式，保留历史和修订号。
也可在备份前主动运行重绑定，提前转换格式；已经换目录恢复的旧备份同样使用此命令：

```powershell
# 当前配置指向恢复位置；旧路径只是查找登记记录，不需要仍然存在。
# 路径和修订号均为示例，替换成备份原位置及其最后确认的修订号。
.venv\python.exe scripts/build_kb.py --rebind-from 'E:\old-project\data\chroma_db' --expected-revision 2
.venv\python.exe scripts/build_kb.py --status
```

若未保存备份修订号，可临时将 `CHROMA_DIR` 配置为原绝对路径运行 `--status`，只读查看旧登记；
随后将配置改回恢复位置，再执行重绑定。此查看不要求原向量目录存在。

重绑定只适用于 Chroma 的绝对位置登记，不合并已有目标登记，也不跨逻辑集合名迁移。
它核对原修订号、活动版本的 Embedding 配置，以及所有 `ready` 集合的 COSINE 度量、
分块数、连续分块 ID、正文与元数据哈希，验证后一次性迁移活动指针、上一版本和全部历史记录。
正文与元数据哈希不包含向量字节；重绑定不会重新生成或证明向量的语义质量。
`failed` 和 `building` 记录原样保留供排查，不把未完成集合变成可发布版本。
校验、冲突或数据库写入失败时事务回滚，登记不变；成功时保留备份原有修订号，后续发布和回滚继续递增。
此命令不调用模型或 Embedding 服务。

本阶段不自动清理历史或失败集合，也不提供跨主机发布协调；历史集合会继续占用存储空间。

Embedding、向量写入或验证失败时，候选记录标为 `failed`，现用指针不变。
进程被强制中止时可能留下 `building` 和部分集合，现用指针仍不变；可重新构建，不要修改旧集合来补齐候选。
候选完成后、发布前退出时，保留 `ready`，可通过上述分步命令发布。
登记库损坏或活动集合失联时，读取失败并显示不可用，不回退到无法核实的集合；应恢复配套备份。

## SQL 存储

个人数据库连接、事务和参数占位符由 `src/storage.py` 管理，鉴权、个人数据和会话共同调用。
SQLite 异常退出回滚并关闭连接，只读连接使用 `mode=ro` 和 `query_only`；PostgreSQL 使用只读事务。
公共课程、校历和浏览器共用公共库只读连接；路径错误不会新建空库。

成绩通过数据库原子更新保存，已有非空课程名和学分快照不会在修改成绩时改变。
重复选课使用冲突忽略；用户与学期继续作为联合主键范围。原有鉴权内部连接别名保留给旧脚本兼容。

## 验证范围

`scripts/test_chroma_rebuild.py` 使用真实临时 Chroma 和确定性向量，覆盖故障、并发发布、回滚、命令与浏览器版本一致性。
`scripts/test_kb_restore.py` 在子进程退出后复制配套文件，覆盖整套目录迁移、旧登记重绑定、
暂存版本恢复、浏览器读取、回滚、并发重绑定和各类失败时的事务保护。
Milvus 通过本机安装驱动的接口与客户端替身验证创建、动态字段、读取、过滤和关闭；未连接真实服务完成发布。
SQL 用临时 SQLite 验证事务、并发和既有接口；PostgreSQL 仅验证参数及只读事务契约，未进行真实服务集成测试。
