# 会话生命周期

日期：2026-10-18

网页顶部可以新建或切换会话。原来的 `{user_id}-main` 保留为“原有会话”，无需迁移检查点。
新会话独立保存聊天上下文和调用计数；长期画像继续按用户共享。

## 刷新与恢复

- 登录或刷新后恢复当前会话；当前选择保存在按用户名区分的 sessionStorage 中。
- 网页历史独立保存在个人数据库的聊天记录表，模型摘要只压缩推理上下文，不裁剪用户可见原文。
- 只展示用户和模型文本，不把工具结果、系统指令或内部摘要显示为用户消息。
- 旧会话首次读取时从保留的检查点按时间补回原文；已被清理且没有任何副本的原文无法凭摘要重建。
- 每条消息按稳定 ID 去重，刷新和确认恢复不会重复插入。后台执行结束后，即使浏览器断连也能读取已保存回复。
- 待确认时展示全部动作，可统一批准或拒绝。刷新后仍可操作。
- 等待确认时不能发送新问题，可以先处理确认，也可以新建会话。

## HTTP 协议

全部接口要求 Bearer token；用户身份只由 token 确定。

| 请求 | 行为 |
| --- | --- |
| `GET /api/conversations` | 列出当前用户的会话，包含原有会话 |
| `POST /api/conversations` | 新建会话，返回 id、标题和创建时间 |
| `GET /api/conversations/{id}` | 返回独立历史、待确认动作、检查点版本、运行状态和额度 |
| `POST /api/chat` | 在指定会话发送消息或恢复确认 |

聊天示例：

```json
{"conversation_id": "服务端返回的 id", "message": "这周有什么课程？"}
```

确认示例：

```json
{
  "conversation_id": "服务端返回的 id",
  "checkpoint_id": "详情或 interrupt 事件中的版本",
  "decisions": [{"type": "approve"}, {"type": "reject"}]
}
```

决定的顺序和数量必须对应全部待确认动作。后端验证允许的决定类型；修改参数时必须保留工具名。
网页目前统一批准或拒绝全部动作；逐项混合决定及参数编辑仅 HTTP 接口支持。
旧客户端省略 conversation_id 时仍使用原有会话；resume 布尔简写仅用于单动作，仍须携带 checkpoint_id。

空输入、同时提交多个操作或决定数量错误返回 422。
无归属的会话返回 404；同会话正在执行、确认版本过期或没有待确认操作时返回 409。
会话额度耗尽后，新消息返回 429，并提示新建会话。

SSE 事件有 token、interrupt、limit、done、error；心跳以注释帧发送。
interrupt 包含 checkpoint_id、允许的决定及动作序号。
limit 提供调用上限说明；done 包含当前累计用量和 exhausted 标记。

## 执行与额度

同会话只允许一个后台执行，不同会话可以独立执行。此保证只覆盖一个 Python 进程，运行时不要增加 uvicorn workers。
检查点和历史读取只持有对应会话的协调锁；全局登记锁不跨越数据库读取，慢会话不再因此阻塞其他会话。
同一会话读取状态时，开始和结束执行仍按顺序协调，避免旧消息被配上错误的空闲标记。
前端忙碌限制和后端执行互斥分别生效，双标签页也不能并发改写同一会话。
断开浏览器连接不会强制终止已经发出的模型请求；后台执行继续，保持会话锁直到结束。
事件队列有容量限制；断连后停止向队列投递。刷新页面可查看运行状态，结束后恢复独立聊天记录。

原始用户消息在执行前保存，完整模型消息更新在下一次摘要前保存。
当前执行发生异常时，尽量保留已流出的部分回复；强制终止进程时尚未完成、未保存的输出不保证完整。
聊天记录仍按账号隔离，包含用户原始输入，模型上下文的 PII 脱敏不会改写用户自己的历史原文。

| 配置 | 默认值 | 范围 |
| --- | --- | --- |
| MODEL_CALL_RUN_LIMIT | 12 | 单次执行的模型调用 |
| TOOL_CALL_RUN_LIMIT | 12 | 单次执行的工具调用 |
| MODEL_CALL_THREAD_LIMIT | 200 | 会话累计模型调用 |
| TOOL_CALL_THREAD_LIMIT | 200 | 会话累计工具调用 |

一次确认恢复是新的执行，单次限额重置，累计限额保留。
工具超限返回错误工具结果，让模型收尾；模型超限结束本轮，并发送明确的 limit 事件。
已有待确认操作仍可提交决定；处理完成后，额度耗尽的会话保留为可查看记录。

## 验证

`scripts/test_conversations.py` 使用临时 SQLite，验证归属、版本化确认、历史投影、并发和真实假模型图的限额。
它还关闭再打开 SQLite 检查点，验证持久化确认可以恢复。
`scripts/test_run_registry.py` 验证跨会话隔离、同会话开始/结束一致性、并发争抢和读取异常后的恢复。
`scripts/test_chat_history.py` 使用真实摘要中间件，验证原文保留、旧检查点补回、重开、确认、脱敏和异常回复。
`scripts/test_frontend.js` 通过专用本机假模型应用验证网页流程，运行方法见[前端说明](frontend.md#浏览器回归)。
真实云模型和 PostgreSQL 的集成验证不属于这些离线检查。

验收摘要场景可运行 `.venv\python.exe scripts/run_frontend_test_app.py --summarize`，再在本机 18765 端口注册测试账号。
连续发送 4 个普通问题后刷新、切换回来，仍应显示全部 8 条原始消息。该应用使用临时数据库与虚构模型，不访问现用个人数据。

## 学期上下文

每轮新消息可携带 `semester_id`，服务端以运行上下文交给工具，不把身份交给模型填写。
处理中和待确认的学期保存在账号所属会话的登记中，读取状态与执行互斥保持一致。
确认恢复如果携带不同学期会返回 409；未携带时沿用原操作学期。
页面在处理或等待确认时锁定选择器，刷新后恢复原选择。详情见[多学期说明](semesters.md)。
